# 📔 Ежедневник

Офлайн-приложение-ежедневник: календарь, дела на каждый день и напоминания.
Написано на чистом HTML/CSS/JS — **без сборки и без зависимостей**. Работает в
браузере, устанавливается на телефон как обычное приложение (PWA) и может быть
собрано в нативный Android-APK с системными уведомлениями по дате.

## Возможности

- Календарь по месяцам, отметки дней с записями и напоминаниями.
- Записи на день: время, название, заметка, отметка «выполнено».
- Повторы: каждый день / неделю / месяц / год.
- Напоминания: показываются в указанное время.
- Тёмная и светлая темы (автоматически по настройкам системы).
- Экспорт и импорт всех данных в JSON — для резервной копии и переноса на телефон.
- Устанавливается на Android как приложение, работает офлайн.

## Онлайн-версия

Опубликовано на GitHub Pages: **https://mr-miha.github.io/daily-book/**
(само приложение лежит по адресу `/planner/`, корневая ссылка на него перенаправляет).

## Быстрый старт на компьютере

Откройте терминал в этой папке и запустите мини-сервер:

```powershell
powershell -ExecutionPolicy Bypass -File .\planner\serve.ps1
```

Затем откройте <http://localhost:8765/>.

Сменить порт: `... -File .\planner\serve.ps1 -Port 8080`.
Остановить сервер: `Ctrl+C`.

> Можно открыть и просто `planner\index.html` (двойным щелчком). Но по `file://`
> не работают service worker, установка приложения и уведомления — для них нужен
> `http://` или `https://`.

## Где хранятся данные

Данные хранятся в `localStorage` браузера (на устройстве, никуда не отправляются):

| Ключ                 | Содержимое                         |
| -------------------- | ---------------------------------- |
| `planner.entries.v1` | массив записей                     |
| `planner.settings.v1`| настройки (выбранная дата)         |

Формат записи:

```json
{
  "id": "UUID",
  "date": "2026-10-20",
  "time": "14:30",
  "title": "Позвонить в сервис",
  "note": "С 14:00 до 16:00",
  "done": false,
  "remind": true,
  "repeat": "none | daily | weekly | monthly | yearly",
  "createdAt": 1792386239826,
  "lastNotified": null
}
```

## Установка на телефон (Android, как PWA)

PWA устанавливается только с `https://` (или `http://localhost`). Способы:

1. Выложить содержимое папки `planner/` на любой https-хостинг
   (GitHub Pages, Netlify Drop, Cloudflare Pages — подойдёт любой статический хостинг).
2. Открыть сайт в Chrome на телефоне.
3. Меню Chrome (⋮) → **Установить приложение** / **Добавить на главный экран**.

Перенос данных: на компьютере нажмите **Экспорт** — скачается
`ежедневник-ДАТА.json`. Перекиньте файл на телефон и нажмите там **Импорт**.

### Про уведомления в PWA

В режиме PWA напоминания срабатывают, **пока приложение открыто** (в том числе
свёрнуто в фоне, пока браузер не выгрузил страницу). Если нужно, чтобы
уведомление приходило строго по времени даже при закрытом приложении — нужна
нативная сборка (ниже).

## Нативная сборка для Android (Capacitor)

Так приложение превращается в настоящий APK, а уведомления планируются системой
на конкретную дату и время и срабатывают даже при закрытом приложении.

Код уже готов: в `planner/app.js` есть автоопределение Capacitor — при наличии
плагина `LocalNotifications` уведомления планируются через него, иначе
используется веб-вариант.

**Требуется Node.js 18+** (на этом компьютере он не установлен).

```powershell
# 1. Создайте рядом с папкой planner проект-обёртку
mkdir dnevnik-android
cd dnevnik-android
npm init -y

# 2. Установите Capacitor (актуальная версия — 8)
npm install @capacitor/core@latest @capacitor/cli@latest @capacitor/android@latest
npm install @capacitor/local-notifications@latest

# 3. Инициализируйте проект, указав веб-папку на наш ежедневник
npx cap init "Ежедневник" ru.example.dnevnik --web-dir ..\planner

# 4. Добавьте android и скопируйте веб-файлы
npx cap add android
npx cap sync android

# 5. Откройте проект в Android Studio и соберите APK
npx cap open android
```

### Точные уведомления (Android 12+)

Чтобы напоминания приходили точно в указанное время, добавьте разрешение в
`dnevnik-android\android\app\src\main\AndroidManifest.xml` (внутри тега
`<manifest>`, рядом с другими `<uses-permission>`):

```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

Затем снова `npx cap sync android`.

- `POST_NOTIFICATIONS` — разрешение на показ уведомлений (Android 13+).
- `SCHEDULE_EXACT_ALARM` — точное срабатывание. Пользователь может отключить его
  в настройках приложения; тогда уведомления станут неточными.
- На Android 14+ вместо `SCHEDULE_EXACT_ALARM` можно использовать
  `USE_EXACT_ALARM`, если точные будильники — ключевая функция приложения.

### После правок веб-части

Любое изменение файлов в `planner/` нужно скопировать в Android-проект:

```powershell
cd dnevnik-android
npx cap copy android
```

## Структура проекта

```
planner/
├── index.html              # разметка: календарь, список записей, форма
├── styles.css              # оформление, светлая и тёмная темы
├── app.js                  # вся логика: записи, повторы, напоминания, экспорт
├── sw.js                   # service worker: офлайн-кэш и клики по уведомлениям
├── manifest.webmanifest    # манифест PWA (имя, иконки, установка)
├── icons/
│   ├── icon.svg            # векторная иконка
│   ├── icon-192.png        # иконка для установки
│   ├── icon-512.png        # иконка для установки
│   └── generate-icons.ps1  # перегенерация PNG-иконок
└── serve.ps1               # локальный веб-сервер для запуска
```

## Обслуживание

- **Иконки.** Пересоздать PNG: `powershell -ExecutionPolicy Bypass -File .\planner\icons\generate-icons.ps1`
- **Обновления приложения.** Service worker работает по схеме «сначала сеть»,
  поэтому свежие файлы подхватываются автоматически. Если меняете список
  файлов оболочки в `sw.js`, поднимите номер `CACHE_NAME` (например, `planner-v4`).
- **Скрипты `.ps1`** должны быть сохранены в **UTF-8 с BOM**, иначе Windows
  PowerShell 5.1 прочитает кириллицу как ANSI и скрипт не запустится.
