# AGENTS.md

Инструкции для агентов OpenCode, работающих в этом репозитории.

## Что это

«Ежедневник» — офлайн PWA (календарь, записи, напоминания) на чистом HTML/CSS/JS.
**Сборки нет, зависимостей нет, пакетного менеджера нет, тестов нет, git не инициализирован.**
Правки в файлах применяются сразу после перезагрузки страницы.

Пользовательская документация — в `README.md` (там же путь сборки под Android через Capacitor).

## Окружение этой машины

- Есть только **Windows PowerShell 5.1** (вызов `powershell`).
- **Нет** Node.js, npm, git. «Python» — заглушка из Microsoft Store (`exit 9009`),
  реального интерпретатора нет.
- Целевое устройство — Android; интерфейс и документация на русском.

## Запуск и проверка

```powershell
powershell -ExecutionPolicy Bypass -File .\planner\serve.ps1 -Port 8765
```

Открыть <http://localhost:8765/>. Остановить: `Ctrl+C`.
`file://` не подходит: там не работают service worker, установка PWA и уведомления.

Автотестов нет. Проверка — вручную в браузере (можно инструментами `browser.*`:
`navigate` → `evaluate` → `screenshot`). Для чистого состояния:
`localStorage.clear()` — ключи `planner.entries.v1` и `planner.settings.v1`.
Lighthouse запускается через `browser.lighthouse`; сейчас все категории = 1.0.

## Архитектура (неочевидное)

- Корневой `index.html` — **только для GitHub Pages**: редирект на `planner/`.
  Локальный запуск его не использует (`serve.ps1` отдаёт папку `planner/`).
- `planner/app.js` — единственный модуль, весь внутри IIFE; функции наружу не экспортируются.
  Внутренние части недоступны из консоли — проверять только через UI/DOM.
- `occurrence(entry, now)` — ядро повторов: возвращает `{last, next}` для
  `none|daily|weekly|monthly|yearly`. `upcomingOccurrences()` строит следующее расписание.
- `notificationGranted()` / `isNative()` / `localNotifications()` — прослойка:
  в браузере веб-уведомления, в Capacitor — `window.Capacitor.Plugins.LocalNotifications`.
  Нативные уведомления синхронизируются в `syncNativeSchedules()` (перевызывается после
  каждого изменения записей).
- Уведомления в PWA работают только пока страница открыта. Планирование «в фоне»
  возможно только в нативной сборке — не пытайтесь реализовать это в веб-коде.

## Подводные камни

- **`.ps1` только в UTF-8 с BOM.** PowerShell 5.1 читает файл без BOM как ANSI и
  падает на кириллице. После правки `.ps1` проверьте и при необходимости верните BOM.
- **Кэш service worker.** `sw.js` работает «сначала сеть». При изменении списка
  `APP_SHELL` поднимайте `CACHE_NAME` (`planner-v3` → `planner-v4`).
- **Контраст.** Lighthouse-доступность должна оставаться 1.0. Не затемняйте текст через
  `opacity` (ломает контраст) — используйте переменные `--muted` / `--faint`, а для текста
  на акцентном фоне — `--on-accent`. Новые цвета оформляйте через переменные темы.
- **Иконки.** `icon-192.png` / `icon-512.png` пересоздаются скриптом
  `planner/icons/generate-icons.ps1`; список иконок должен совпадать с `manifest.webmanifest`.
